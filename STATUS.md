## What this component does not claim

- **No confinement unless it is asked for.** Confinement is opt-in — `--substrate` or
  `--substrate-embedded` — and a run that names neither publishes **no writing and no executing
  tool**: `file_write`, `file_edit` and `run` are absent from what the machine admits, so, like the
  model-only Codex routes under ADR 0051, this harness's effects are exactly what its published
  toolset admits and nothing constrains it further. That is a claim about what the published tools
  can *do* and never about how many there are: the count varies with the run — `--surface verbs`
  publishes three (`tool_search`, `tool_describe`, `tool_invoke`) over the same catalogue, and
  `--output-schema`, `--delegate` and `--skills-dir` each add one the loop owns (`answer`,
  `delegate`, `skill`), none of which writes or executes either. What the *Substrate confinement*
  row claims is that the capability exists and works, never that it is the default.
- **No live-provider conformance.** Both routes have now been *run* against the real vendor — see
  the Subscription auth row — but every pinned contract is still emulator-derived, and a run is not
  a conformance pin. The deterministic local endpoint proves the pieces agree with each other; it
  proves nothing about the bytes a real provider sends
- **No multimodal input.** It remains a decision about what the neutral wires own. Outbound MCP is
  now implemented as a lower transport foundation plus Harness-owned reviewed authority; it does
  not change metaharness's ownership of driving somebody else's loop.
- No realtime media and no **provider-side** sessions. A session here is this harness's own
  file on this machine: turns stay stateless, nothing is retained on the far side, and the whole
  conversation is replayed every turn (invariant 4).
- No hosted service, no admission transport, no durable store.
