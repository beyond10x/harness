# Harness documentation site

The public site at <https://beyond10x.github.io/harness/>. It is Docusaurus on the shared
beyond10x Docs System (`@beyond10x/docs-system`, pinned by commit in `package.json`), served under
`/harness/`. The site build is the only Node in this repository; everything derivable is
generated by the Rust crate `crates/harness-docs`.

## What is generated and what is written by hand

| Path | Source |
|---|---|
| `docs/reference/cli.md` | Generated from the clap definition of `b10x-harness` |
| `docs/reference/toolchains.md` | Generated from the built-in toolchain specifications |
| `docs/reference/crates.md` | Generated from `cargo metadata` |
| `docs/status.md`, `data/status.json` | Generated from the capability list in `crates/harness-docs/src/status.rs` |
| `docs/index.md`, `docs/getting-started.md`, `docs/limitations.md`, `docs/tutorials/`, `docs/concepts/`, `docs/guides/`, `docs/reference/configuration.md`, `docs/reference/wires.md` | Written by hand |
| `product.json` | The landing page (`b10x-product-landing/1`), written by hand |
| `docusaurus.config.ts`, `sidebars.ts` | Site configuration and the explicit sidebar |

Never edit a generated file by hand. From the repository root:

```console
cargo run --locked -p harness-docs -- generate
cargo run --locked -p harness-docs -- generate --check
```

`generate` rewrites the generated files. `generate --check` writes nothing and fails on a
generated file that is missing, stale or edited, and on any page that breaks the rules below. The
source gate (`cargo xtask gate`) runs the check. `task docs-generate` and `task docs-check` are the
same two commands.

## Page rules

Every page under `docs/` is plain Markdown (`.md`, never `.mdx`) with front matter:

- `title`, `sidebar_position` and `description` on every page; concept and guide pages also carry
  `lede` (the sentence the page opens on) and `source` (the files and commands it is written from).
- A front matter value that YAML would not read as one string (it contains `: ` or ` #`, ends with
  `:`, or starts with a YAML indicator) must be quoted.
- Outside code: no `{`, no `import` or `export` line and no capitalised tag. The unified
  documentation site still collects these pages and refuses executable MDX.
- Callouts are admonitions with the title in brackets, `:::caution[Planned]`; Docusaurus prints an
  unbracketed title as raw text.
- No page points at internal material (design records, planning stores, `STATUS.md`,
  `ROADMAP.md`, the organization map). `docs/index.md` names the workspace version, so a release
  updates it.
- Links between pages name the `.md` source. Docusaurus refuses a broken link, anchor or Markdown
  link at build time.

## Build and preview

Node 22. The Docs System is a Git dependency, which npm installs only with `--allow-git=root`
(set in `.npmrc`).

```console
cd website
npm ci --allow-git=root
npm run build
npm run serve
```

`npm run build` writes `website/build`; `npm run start` serves a live-reloading preview. A changed
dependency is installed with `npm install --allow-git=root` and lands as a reviewed
`package-lock.json` change.

## Provenance and delivery

```console
cargo run --locked -p harness-docs -- provenance --site website/build --commit "$(git rev-parse HEAD)"
```

`provenance` binds a built site to the commit it was built from. It writes
`.well-known/b10x-site.json` (schema `b10x-project-site/v1`, with the repository, the commit and
the `/harness/` base) and the route inventory `.well-known/b10x-routes.json`, and adds `.nojekyll`.

Building and deploying are separate, and this repository holds no deployment credential:

- `.github/workflows/pages.yml` runs on every push and pull request with `contents: read` only and
  persists no checkout credential. It builds the site, runs the `harness-docs` tests (which include
  `generate --check` on the tree) and `provenance`, and on a
  push to `main` uploads the result as the artifact `b10x-project-site`. It deploys nothing.
- `.github/workflows/b10x-docs-site.yml` runs after a green `pages.yml` push to `main`, only for the
  bot. It calls the shared `project-site.yml` publisher in the Website repository, pinned by commit,
  which downloads that exact artifact, verifies its manifest against the commit and base, and
  deploys it to Pages. It never runs this repository's code.

## Security boundary

- The browser gets the static output of the Docusaurus build: no third-party fonts, scripts or
  analytics are added by this site.
- The pages are passive Markdown (see the page rules), so a page cannot run code at build time.
- npm resolves dependencies from `package-lock.json` and installs the one Git dependency, the Docs
  System, at the commit `package.json` pins.
- CI builds with `contents: read` and no credential; deployment is the shared publisher's.

Report a vulnerability through the repository's
[private security policy](https://github.com/beyond10x/harness/security/policy).
